# 추론기 배치 스택 구성 — isaac 1단계

> **상태: 설계안 (2026-09-21). 코드 미반영.** ACT 로 학습한 추론기를 **isaac 안에서** 돌리기 위한 로봇 스택의
> 구성이다. 미구현 항목 **P1(추론 노드) · P2(컨트롤러 어댑터) · P3(조건 대조)** 를 만들 때의 출발점이다
> ([미구현_목록.md](미구현_목록.md) §6).
> 배치 규약(무엇을 지켜야 하나)의 정본은 [학습_샘플_사양.md](학습_샘플_사양.md) §6 이다. 이 문서는 그 규약을
> **어떤 스택 · 어떤 노드로 실현하나**와, 규약에 아직 없던 걸림돌 셋(§5)을 다룬다.
> 확인 근거는 2026-09-21 기준이다 — lerobot 0.4.4 소스, `rdfp-train` 의 `train.py`, isaac 백엔드 프로파일 ·
> 컨트롤러 설정, 실데이터 export(`/data/rdfp/datasets/v1`). 위치는 부록 A.

## 1. 한 줄 답

**데이터를 모은 isaac 스택 그대로**다. 트윈과 수집 루프가 팔을 움직이던 자리에 **추론 노드 하나(P1)와 명령
어댑터(P2)** 를 꽂고, 나머지는 학습 때와 한 비트도 다르지 않게 둔다.

이 추론기는 **isaac 줄(Panda + Panda Hand)** 에서 학습했으므로 isaac 안에서만 쓴다. 실기(Panda + Robotiq 2F-85)는
펑션베이 줄로 따로 간다 — 두 줄의 데이터와 추론기를 섞지 않는다([결정_기록.md](결정_기록.md) 1 · 2). 이 단계에는
도메인 갭이 없으므로, 여기서 안 되면 원인은 학습 또는 배치 규약 쪽에 있다.

## 2. 구성도

```
Isaac Sim (같은 씬: 탁자 상면 0.3 · 실린더 r 0.03 · 카메라 8° 상향)
   │ /isaac/camera/image_raw (rgb8 640×480)            ▲ /isaac/arm_command
   ▼                                                   │
panda_isaac.launch.py
   (ros2_control TopicBasedSystem · JTC open_loop_control · joint_state_broadcaster ·
    gripper_action_node · isaac_scene_state_node · move_group)
   │
   ├─ /joint_states · /gripper_states ───────┐
   │                                         ▼
   │                              [추론 노드 P1]
   │                              ACTPolicy + 전처리기 + 후처리기
   │                              + 조건 대조 P3 (rdfp_spec.json)
   │                                         │
   ◀─ /panda_arm_controller/joint_trajectory ─┤  [어댑터 P2] 단일점, time_from_start = Δ 기준
   ◀─ /gripper_cmds ──────────────────────────┘  심볼, 바뀔 때만

(선택) robot_twin : 평가 전 reset_scene · return_home, 평가 후 verify
(선택) rdfp_collect + rosbag : 롤아웃 녹화 — 실패 분석용
```

로봇 스택은 [../backends/isaac/isaac_bringup_runbook.md](../backends/isaac/isaac_bringup_runbook.md) §2 의 터미널 1 ·
2(시뮬레이터 · `run_panda_isaac.sh`)와 같다. 바뀌는 것은 터미널 5(작업 수행)가 `robot-twin-collect` 대신 추론 노드가
된다는 것뿐이다.

## 3. 학습 때와 같아야 하는 것 — 관측

**어긋나도 에러가 안 나고 "학습은 됐는데 잘 안 된다"로만 나타난다.**

| 입력 | 학습 때 | 추론 노드에서 |
|---|---|---|
| 영상 | `/isaac/camera/image_raw`, **`rgb8`** 640×480 (프로파일 `camera.pixel_format`) | 학습 로더가 mp4 를 `rgb24` 로 디코드했으므로 **RGB 순서 그대로** 쓴다 — BGR 로 바꾸지 않는다. uint8 → float/255, HWC → CHW. 해상도를 줄이지 않는다 |
| `qpos[:7]` | `/joint_states` 를 프레임 stamp 에서 선형 보간 | `spec.arm_joints`(`panda_joint1`~`7`) 순서로 **이름으로 골라** 쓴다. 인덱스로 자르지 않는다 — 손가락 관절이 섞여 있다. 100 Hz 라 최신값을 써도 오차는 10 ms 안이지만, 프레임 stamp 에서 보간하는 것이 학습과 같다 |
| `qpos[7]` | `/gripper_states.width` — **개구 폭(m)** | 손가락 관절값이 아니라 `width` 를 쓴다 (Panda 는 관절값의 2 배다) |
| 시계 | `use_sim_time: true` | 노드도 sim time 으로 돈다. 프레임 stamp · 명령 시각을 같은 시계로 비교한다 |
| 씬 · 카메라 | 탁자 0.3, 실린더 r 0.03, 카메라 (1.35, 0, 0.85) 수평 아래 24.905° | `isaac_scene.json` 을 바꾸지 않는다. 바꾸면 **재수집 · 재학습**이다([결정_기록.md](결정_기록.md) 35) |
| 시작 상태 | `return_home` 으로 `ready`, 그리퍼 open, 같은 레시피의 무작위 배치 | 평가마다 `reset_scene` → `return_home` 을 먼저 부른다 (§8) |

## 4. 행동을 넣는 법 — 어댑터(P2)

### 4.1 팔

- **JTC 에 단일점 `JointTrajectory` 를 보낸다** — 토픽 `/panda_arm_controller/joint_trajectory`, 관절 이름을 채운다.
- **`time_from_start` 는 프레임 stamp 기준으로 잡는다.** 행동 스텝 j 의 목표 시각은 `τ_j = t_i + Δ + j × 100 ms`
  이고 `t_i` 는 그 영상의 stamp 다. 추론 지연만큼 이미 지나 있으므로 `time_from_start = τ − now` 로 준다
  (`now` 기준으로 Δ 를 더하면 매 스텝 지연만큼 늦어진다).
- **`open_loop_control: true` 는 이미 켜져 있다** (`config/panda_isaac_ros2_controllers.yaml`). 이것이 없으면 JTC 가
  새 궤적마다 측정 상태에서 보간을 다시 시작해, 부하로 처진 만큼이 명령에 적분된다 — servo 래칫과 같은 원리다
  ([../teleop/servo_vs_planned_motion.md](../teleop/servo_vs_planned_motion.md) §3~§4). 기동 시점에만 읽히므로
  `param set` 으로는 못 바꾼다.
- **10 Hz 목표를 계단으로 그대로 넣지 않는다** — JTC 가 보간하게 둔다. 펑션베이에서 계단 명령으로 peg 삽입이
  실패한 실측이 있다([결정_기록.md](결정_기록.md) 26).
- **출발점은 재생용 `target_joint_cmds_executor` 다** — `JointState` 를 단일점 `JointTrajectory` 로 감싸 JTC 에
  넣는 노드이고 `time_from_start` · `joint_names` 파라미터가 있다. 다만 고정 `time_from_start` 라 위의 stamp 기준
  계산은 새로 해야 한다.

### 4.2 그리퍼

one-hot 의 argmax 를 심볼(`open` · `close` · `grasp`, 이 순서가 계약)로 되돌려 `/gripper_cmds` 에 낸다.
**같은 심볼이 이어지면 다시 보내지 않는다** — 매 스텝 보내면 `GripperActionNode` 가 매번 새 goal 로 선점한다.

### 4.3 안전 — MoveIt 을 거치지 않는다

정책의 명령은 `move_group` 을 거치지 않으므로 **충돌 검사가 없다.** 어댑터가 최소한 둘을 막는다.

| 가드 | 이유 |
|---|---|
| 관절 한계로 자른다 (`panda_real_joint_limits.yaml`) | Isaac 은 한계를 강제하지만, `panda_joint6` 하한은 손목 특이점과 같은 자리라 거기 들어가면 빼낼 수단이 없었다(CLAUDE.md) |
| 한 스텝의 관절 변화량을 제한한다 | 정규화가 틀렸거나(§5.1) 관측이 튀면 한 스텝에 큰 점프가 나간다 |

`move_group` 은 떠 있어도 된다 — `ready` 복귀(`return_home`)에만 쓴다.

## 5. 추론 노드(P1) — 확인된 걸림돌 셋

### 5.1 ⚠️ 체크포인트에 후처리기(역정규화)가 없다

`train.py` 가 `preprocessor, _ = make_act_pre_post_processors(...)` 로 **후처리기를 버리고**, `_save()` 는 정책과
전처리기만 저장한다. lerobot 0.4.4 에서 역정규화는 후처리기(`UnnormalizerProcessorStep`)의 일이라, 정책 출력을
그대로 쓰면 **정규화된 값이 관절 목표로 나간다** — 에러 없이 엉뚱한 곳으로 움직인다.

통계 자체는 전처리기에 들어 있다(`NormalizerProcessorStep` 이 입력과 출력 feature 를 모두 받는다). 그래서 복원은
할 수 있지만, **학습(D4)을 돌리기 전에 `train.py` 가 후처리기까지 저장하게 고치는 것이 맞다** — 체크포인트는
"정책 + 전처리기 + 후처리기 + `rdfp_spec.json`" 이 한 묶음이어야 한다.

### 5.2 ⚠️ lerobot 의 temporal ensembling 은 호출 횟수로 스텝을 센다

- 저장된 config 는 `chunk_size=20` · `n_action_steps=20` · `temporal_ensemble_coeff=None` 이다. 앙상블을 쓰려면 로드
  때 `temporal_ensemble_coeff`(원 논문 0.01)와 `n_action_steps=1` 로 덮어써야 한다 — lerobot 이 둘을 함께 강제한다.
- **`ACTTemporalEnsembler.update()` 는 호출 한 번에 한 칸씩 민다.** 우리 행동 스텝은 **시각**(100 ms)으로 정의돼
  있고, isaac 카메라는 **15 % 가 200 ms 를 넘긴다**(100 ms 정수배로 렌더를 건너뛴다 — 65 에피소드 11,654 간격
  실측). 프레임이 올 때마다 부르면 **빠진 프레임만큼 앙상블이 어긋나** 다른 시각의 예측끼리 평균된다.

| 선택지 | 방법 | 대가 |
|---|---|---|
| (a) 고정 타이머 | sim time 100 ms 타이머로 매 스텝 `select_action`. 새 프레임이 없으면 직전 영상 재사용 | 간단하다. 빠진 프레임 구간에서 영상이 최대 수백 ms 오래된다 — 학습 샘플에는 없던 상황이다 |
| **(b) 시각 인덱스 앙상블** | chunk 를 그 프레임 stamp `t_i` 와 함께 쌓아 두고, 스텝 시각 τ 마다 `τ = t_i + Δ + j × 100 ms` 인 예측을 모아 가중 평균 | 직접 짜야 한다(수십 줄). **isaac 프레임 stamp 가 100 ms 격자라 chunk 들이 정확히 맞물린다** |
| (c) 앙상블 없음 | chunk 앞 n 스텝을 실행하고 다시 추론 (`n_action_steps` < 20) | 가장 단순하다. chunk 경계에서 행동이 끊길 수 있다 |

**권고는 (b)** — 학습의 정의(행동은 시각의 함수)와 같은 방식으로 섞는다. (c) 를 비교 기준으로 함께 둔다.
펑션베이 줄은 프레임 간격이 격자가 아니라(9.54~9.60 Hz) (b) 에 가장 가까운 격자점 보간이 필요하다 — 그때 다시 본다.

### 5.3 실행 환경과 지연

- **노드는 ROS Humble 의 Python 3.10 에서 `rclpy` 와 `lerobot==0.4.4` · torch 를 함께 import 한다.** rdfp-train 의
  venv 도 시스템 Python 3.10.12(`/usr`)로 만들어져 있어 ABI 는 맞는다. 다만 `--system-site-packages` 없이 만들어졌으므로
  [../python_env_guide.md](../python_env_guide.md) 의 예외형대로 **활성화하지 않고 `PYTHONPATH` 끝에** 붙인다
  (앞에 두면 ROS 경로를 가린다).
- **추론이 100 ms 안에 끝나야 한다** — 늦으면 chunk 가 오래된 시각을 가리킨다. 정책은 51.6 M 파라미터이고
  **Isaac 과 같은 GPU 에서 잰 적이 없다.** 첫 작업으로 잰다. (학습 중에는 GPU 를 나누지 않기로 했지만 배치는
  같은 머신이 자연스럽다.)
- 정책은 `ACTPolicy.from_pretrained(<체크포인트>)` 로, 전처리기 · 후처리기는 각각의 `from_pretrained` 로 읽는다.
  `policy.reset()` 을 **평가 회차마다** 부른다 — 앙상블 · 행동 큐가 이전 회차를 들고 있다.

## 6. 조건 대조(P3)와 정지

### 6.1 조건 대조

체크포인트의 `rdfp_spec.json` 에서 학습 쪽 `ExportSpec` 을 읽고, 배치 스택 쪽 값으로 만든 `ExportSpec` 과
`assert_compatible()` 로 대조한다. **어긋나면 기동을 거부한다.**

| 키 | 대조 | 이번 데이터 |
|---|---|---|
| `label` · `delta_sec` · `step_sec` · `chunk_len` · `arm_joints` · `gripper_symbols` | 엄격 | `joint_plan` · 0.1 · 0.1 · 20 · `panda_joint1`~`7` · `open`/`close`/`grasp` |
| `camera_hz` | 상대 20 % | **5.04** — 실측 평균이다(설정 10 Hz). 같은 Isaac 설정이면 배치 쪽도 비슷하게 나와 통과한다. 배치 쪽 값은 기동 후 수 초 동안 재서 넣는다 |
| `backend` | 양쪽 값이 있을 때만 | **null** (R4 미구현) — 대조되지 않는다. isaac → isaac 이라 1단계에는 문제없다 |
| `camera_topic` · `kinematic_model_hash` | 대조하지 않는다 | 2단계(실기)에서는 지문 대조가 필수다([추론기_배치_목표와_설계_이슈.md](추론기_배치_목표와_설계_이슈.md) §4.2) |

### 6.2 정지 조건

정책은 끝을 모른다 — 학습의 `is_pad` 로 "끝에서 그 자리를 유지"를 배웠을 뿐이다. 다음 중 하나로 멈춘다.

- **시간 제한** — 학습 에피소드는 프레임 61~229 개(중앙값 191), 실효 5 Hz 로 약 12~45 초다. 60 초를 상한으로 둔다.
- **성공 판정** — 트윈의 `scene_objects` 로 `verify_stacked` 가 서면 멈춘다(`robot-twin-client` 의 것을 그대로 쓴다).

## 7. 꺼 두는 것

| 끄는 것 | 이유 |
|---|---|
| `teleop_keyboard` | 기동 시 servo 를 자동 시작한다. 시작된 servo 는 **명령이 없어도 팔을 끌고 가고**(Isaac 실측 10 초에 32 mrad), 어댑터와 **같은 JTC 토픽을 두고 싸운다.** `servo_node` 자체는 `start_servo` 를 부르지 않으면 무해하다 |
| 트윈의 팔 연산, `robot-twin-collect` · `robot-twin-stack` | 같은 이유 — 팔을 지휘하는 주체가 둘이 된다. 트윈은 떠 있어도 되고 `reset_scene` · `return_home` · 상태 조회에만 쓴다 |
| 두 번째 Isaac | 같은 `ROS_DOMAIN_ID` 에 둘이면 `/clock` · `/tf` 발행자가 겹쳐 `TF_OLD_DATA` 가 쏟아지고 배치가 seed 와 무관해진다 |

## 8. 평가 루프

수집 루프(`robot-twin-collect`)와 같은 모양이고 팔을 움직이는 주체만 바뀐다.

```
for seed in seeds:
    트윈 reset_scene(seed)          # 에피소드 밖에서 배치 — 학습과 같다
    트윈 return_home                # ready, 그리퍼 open
    (선택) start_episode             # 롤아웃을 녹화할 때만
    추론 노드 활성화 → 정지 조건(§6.2)까지 → 비활성화   # 서비스로 켜고 끈다, 켤 때 policy.reset()
    verify_stacked() → 성공 / 실패
    (선택) stop_episode(outcome, metadata={seed, checkpoint, ...})
```

- **추론 노드는 서비스로 켜고 끈다** — 켜져 있는 동안만 명령을 낸다. 꺼진 동안 트윈의 `return_home` 과 겹치지 않게.
- **롤아웃을 녹화하면 실패 분석이 된다.** `rdfp_collect` 를 함께 띄우면 영상 · `/joint_states` · `/gripper_*` 가
  남고, 정책의 팔 명령은 `/target_joint_cmds` 로 남는다(`target_joint_cmds_publisher` 가 JTC 의 `joint_trajectory` 를
  원천으로 받는다). **R1/R2(`motion/*`)는 나오지 않는다** — 정책이 `MoveGroupClient` 를 거치지 않기 때문이다.
  이 롤아웃은 학습 데이터가 아니라 평가 기록이다 — 같은 `rosbag_dir` 에 섞지 않는다.
- **학습에 쓰지 않은 seed 로 평가한다.** 수집에 쓴 seed 는 `sessions.metadata` 에 남아 있다.
