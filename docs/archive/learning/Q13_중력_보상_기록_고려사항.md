## 1. 무엇을 정하는가

**"이 학습 데이터의 행동값에 중력 보상 오프셋이 들어 있는가"를 데이터가 스스로 말하게 하는 방법**이다. 갈래는 다섯이고, 원래 질문(`ExportSpec` 에 필드를 넣을까)은 그중 하나일 뿐이다.

| # | 정할 것 | 절 |
|---|---|---|
| 1 | **값을 어디서 얻나** — 수집이 기록하나, export 가 유도하나, 데이터에서 검출하나 | §3 |
| 2 | **입도** — 데이터셋 하나에 한 값인가, 에피소드마다인가 | §4 |
| 3 | **무엇을 기록하나** — `bool` 인가, 보상을 되돌릴 수 있는 기술자인가 | §5 |
| 4 | **`STRICT_KEYS` 에 넣나** | §6 |
| 5 | 이름 | §10 |

## 2. 왜 필요한가 — 오늘은 말할 수 없다

**배치에서 틀리면 이중 보상이나 누락이 나고, 둘 다 오류 없이 일어난다**(수집 설계 §9). 규칙 자체는 간단하다.

| `label` | `backend` | 오프셋 |
|---|---|---|
| `joint_plan` | 아무거나 | **없다** — R1 이 보상 전 경유점을 싣는다(D13) |
| `joint_command` | `functionbay` | **있다** (MoveIt 경로 한정 — §4 의 ⚠️) |
| `joint_command` | 그 밖 | 없다 |

**문제는 이 규칙을 오늘 적용할 수 없다는 것이다.** 유도의 재료인 `backend` 가 `sessions.metadata` 에서 오는데 **R4 미구현이라 항상 `None`** 이다. `build_metadata` 가 그 사실을 `notes` 에 남기기는 한다:

```
backend is unknown — episode metadata did not record it (R4)
```

즉 **지금 만든 관절-명령 데이터셋은 오프셋 포함 여부를 어떤 방법으로도 말하지 못한다.**

> **1차 학습은 막히지 않는다** — 관절-계획에는 오프셋이 없고 배치 경로에서 보상을 건다(수집 설계 §0.4). 이 항목이 사는 곳은 **관절-명령을 비교 기준으로 쓸 때**(E5)와 **나중에 데이터를 섞을 때**다.

## 3. 값을 어디서 얻는가

넷이 있고 **성격이 다르다** — 하나는 사실을 남기고, 둘은 추론하며, 하나는 측정한다.

| | 방법 | 평가 |
|---|---|---|
| **(가)** | **수집이 기록한다** — 에피소드 metadata 에 보상 설정을 싣는다 | **사실을 남긴다.** 다만 **R4 의 키 목록에 보상 정보가 없다**(아래 ⚠️) |
| (나) | **export 가 유도한다** — `label` × `backend` 규칙(§2) | `backend` 가 R4 전까지 `None` 이다. 그리고 **R8 이 들어오면 규칙이 바뀐다** |
| (다) | **사람이 CLI 로 넘긴다** — `export --gravity-offset yes/no` | R4 없이도 오늘 된다. **사람이 틀리면 조용하다** |
| (라) | **데이터에서 검출한다** — 명령과 R1 보간의 잔차를 본다 | 펑션베이 JGPC 에서는 잔차가 **정확히 오프셋**이다(R8 §4). 다른 백엔드에서는 컨트롤러 보간이 섞여 판별이 안 된다 |

⚠️ **R4 의 키 목록을 넓혀야 한다** ([R4 고려사항](R4_에피소드_metadata_규약_고려사항.md) §4 가 이 항목을 받아 판정표에 넣었다). 미구현 목록 R4 가 세는 키는 `backend` · 속도 배율 · 펑션베이 `publish_rate` · 씬 · 계획 파이프라인 · 생성 호스트다 — **보상 설정이 없다.** (가)로 가려면 R4 에 그 항목을 더해야 하고, 그러면 Q13′ 가 R4 에 **좋은 방향으로** 의존한다(유도 대신 기록).

`sessions.metadata` 는 자유 JSON object 라 **스키마 변경 없이** 들어간다 — 백엔드 프로파일의 `motion.gravity_compensation` 블록을 그대로 실으면 된다.

## 4. 입도 — 데이터셋인가 에피소드인가

**⚠️ 지금 export 는 `backend` 를 첫 에피소드에서만 읽는다.**

```python
spec = ExportSpec(..., backend=episode_backend(conn, ids[0]))   # writer.py:319
```

그래서 **백엔드가 섞인 데이터셋을 만들어도 드러나지 않는다** — `metadata.json` 에는 첫 에피소드의 값이 적히고, 나머지는 말없이 그 이름 아래 들어간다. `assert_compatible` 은 학습 ↔ 배치를 비교할 뿐 **데이터셋 안의 균질성은 아무도 안 본다.**

오프셋 플래그를 같은 자리에 넣으면 **같은 구멍을 물려받는다.**

그리고 섞임은 가정이 아니다:

| 언제 | 왜 |
|---|---|
| 백엔드를 섞을 때 | isaac(오프셋 없음) + 펑션베이(있음) |
| **같은 펑션베이 안에서 출처가 갈릴 때** | **MoveIt 경로는 보상하고 teleop(servo) 경로는 보상하지 않는다**(R8 §9) — 한 백엔드 안에서 값이 갈린다 |
| 벤더가 A-1 을 반영한 전후 | 보상을 끄면 그 뒤 에피소드만 오프셋이 없다 |

**그래서 값은 에피소드마다 정해지고, 데이터셋 값은 그것들이 모두 같을 때만 성립한다.**

## 5. 무엇을 기록할 것인가

| | 형태 | 평가 |
|---|---|---|
| **(A)** | `gravity_offset_included: bool` | 가장 싸다. **"있다"만 알고 얼마인지는 모른다** — 되돌릴 수 없다 |
| **(B)** | 보상 **기술자** — `{urdf, kp, scale}` (또는 그 해시) | 되돌릴 수 있다(역보상). 기구학 지문(R3/I2)과 성격이 같다 |
| (C) | `notes` 문자열만 | 사람은 읽지만 **기계가 못 건다.** 지금 상태다 |

**(B) 를 고르면 R8 의 절반이 필요 없어진다** — 오프셋이 `q` 의 결정적 함수이므로 기술자가 있으면 적재나 export 에서 역보상할 수 있다(수집 설계 §6 권고 5 의 (b)). 다만 **역보상에 벤더 URDF 와 `GravityCompensator` 가 필요하고**, 그것을 export 계층에 들이는 것은 지금 없는 의존이다.

**둘은 배타가 아니다** — `bool` 을 `ExportSpec` 에(검사용), 기술자를 `sessions.metadata` 에(복원용) 두는 조합이 자연스럽다. 검사는 싸야 하고 복원은 드물기 때문이다.

## 6. 검사에 넣을 것인가

`ExportSpec` 의 대조는 세 층이다(E7 §6.3).

| 층 | 키 | 동작 |
|---|---|---|
| 엄격 | `label` · `delta_sec` · `step_sec` · `chunk_len` · `arm_joints` · `gripper_symbols` | 다르면 올린다 |
| 관대 | `camera_hz` | 상대 20 % 까지 |
| 조건부 | `backend` | **양쪽 다 값이 있을 때만** 비교 |
| 미검사 | `camera_topic` · `kinematic_model_hash` | 비교하지 않는다 |

**오프셋은 엄격이어야 한다.** 어긋남의 대가가 `camera_hz` 와 다르다 — 주기는 조금 밀리지만 오프셋은 **팔이 두 배로 처지거나 보상 없이 움직인다.**

⚠️ **`backend` 식 "한쪽이 비면 넘어간다"를 따라하면 안 된다.** 그러면 값이 없는 옛 데이터가 조용히 통과한다. **모르면 모른다고 올리는 쪽**이 맞다 — 다만 그러면 R4 이전 데이터가 전부 막히므로, **`Optional[bool]` 로 두되 `None` 을 만나면 경고가 아니라 거부**할지는 정해야 한다(§10 Q2).

## 7. 권고

**단계로 나눈다. 오늘 할 수 있는 것과 R4 를 기다려야 하는 것이 다르다.**

| 단계 | 무엇 | 언제 |
|---|---|---|
| **1** | **`episodes.jsonl` 에 에피소드마다 값을 싣고, export 가 균질성을 확인한다.** 값의 출처는 당장은 (다) CLI 플래그 | **지금** — R4 를 안 기다린다 |
| **2** | `ExportSpec` 에 `gravity_offset_included: Optional[bool]` 을 더하고 **`STRICT_KEYS` 에 넣는다** | 1 과 함께 |
| **3** | **R4 의 키 목록에 보상 설정을 넣는다** — `sessions.metadata` 에 `motion.gravity_compensation` 블록을 그대로 | R4 할 때 |
| **4** | 3 이 되면 export 가 CLI 플래그 대신 **metadata 에서 읽는다.** 플래그는 덮어쓰기용으로 남긴다 | R4 뒤 |

**1 을 먼저 두는 이유**는 §4 다 — 필드를 `ExportSpec` 에만 넣으면 **첫 에피소드 문제를 물려받아** 섞임이 안 드러난다. **에피소드마다 싣고 확인하는 것이 필드보다 먼저다.**

**`backend` 도 같은 처지다.** 균질성 확인을 만들 때 오프셋만이 아니라 **`backend` 도 함께 본다** — 지금 `ids[0]` 에서만 읽는 그 값이다.

## 8. 검증

| 확인할 것 | 합격 기준 |
|---|---|
| **섞인 데이터셋이 거부된다** | 서로 다른 값의 에피소드를 한 번에 export 하면 **올린다**. 지금은 조용히 통과한다 |
| `backend` 도 같이 걸린다 | 백엔드가 섞여도 같은 검사가 잡는다 |
| 배치 대조가 실제로 걸린다 | 오프셋 값이 다른 `ExportSpec` 으로 `assert_compatible()` 이 올린다 |
| `joint_plan` 은 항상 `False` | 레이블이 관절-계획이면 백엔드와 무관하게 `False` 다(R1 이 보상 전이므로) |
| 옛 데이터 | 값이 `None` 인 에피소드를 만났을 때의 동작이 **정해진 대로**다(§10 Q2) |
| (라) 검출과 대조 | 펑션베이 JGPC 에서 `명령 − 보간(R1)` 이 `offset(q)` 와 맞는다 — `ready` joint4 **+9.67 mrad** |

## 9. 주의

- ⚠️ **부호**: `offset = −deficit`, `보상후 = 보상전 + offset`. `ready` joint4 에서 **`deficit = −9.67` · `offset = +9.67 mrad`** 다(2026-09-19 실측 계산). 플래그를 다루는 코드가 부호를 만질 일은 없지만, **검증(§8 마지막)에서 대조할 때 틀리기 쉽다** — R8 문서가 그 실수를 한 번 했다.
- ⚠️ **`joint_plan` 이 `False` 인 것은 "보상하지 않는다"는 뜻이 아니다.** 레이블에 오프셋이 없다는 뜻이고, **배치는 보상을 걸어야 한다**(수집 설계 §0.4 · §9). 이름이 그 오해를 부르면 이름을 바꾼다(§10 Q1).
- ⚠️ **R8 이 들어오면 (나) 의 유도 규칙이 바뀐다.** 보상 전 명령이 별도 채널로 남으면 `joint_command` + `functionbay` 도 오프셋이 없을 수 있다. **그래서 유도보다 기록이 낫다.**
- **벤더가 A-1 을 반영하면** `functionbay.yaml` 의 블록을 지워 보상을 끈다 — 그 전후 데이터가 갈리므로 §4 의 균질성 확인이 그때 값을 한다.

## 10. 열린 질문

| # | 질문 | 정하는 방법 |
|---|---|---|
| Q1 | 이름 — `gravity_offset_included` 인가 | 더 일반적인 이름(`command_postprocessing` 등)이면 나중에 다른 보정이 생겨도 쓴다. 다만 지금은 보정이 하나뿐이라 **구체적인 이름이 읽기 쉽다** |
| Q2 | 값이 `None` 인 옛 데이터를 어떻게 하나 | 거부 / 경고 / 통과. **거부가 안전하지만 R4 이전 데이터가 전부 막힌다.** 그 데이터를 쓸 일이 있는지로 정한다 |
| Q3 | 기술자(§5 의 B)를 함께 남길 것인가 | 역보상을 실제로 할 계획이 서면 필요하다. R3/I2(기구학 지문)와 같은 자리에 두는 것이 자연스럽다 |
| Q4 | 균질성 확인을 오프셋·`backend` 말고 어디까지 넓히나 | `camera_topic` · `arm_joints` 도 에피소드마다 다를 수 있다. **확인 자체를 일반화할지**를 정한다 |
