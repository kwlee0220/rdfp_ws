## 1. 무엇을 정하는가

**에피소드마다 "이 데이터가 어떤 조건에서 만들어졌는가"를 남기는 규약**이다. 자리는 이미 있다 — `sessions.metadata`(jsonb)이고 `StopEpisode` 서비스가 JSON object 문자열로 받는다. **비어 있는 것은 자리가 아니라 규약이다.**

정할 것은 넷이고, 원래 질문(Q5 의 키 목록)은 그중 하나다.

| # | 정할 것 | 절 |
|---|---|---|
| 1 | **누가 채우나** — 호출자인가 시스템인가 | §2 · §7 |
| 2 | **언제 채우나** — 종료 시점뿐인 지금이 맞나 | §3 |
| 3 | **무엇을 담나** (Q5) — 그리고 **담지 말아야 할 것** | §4 |
| 4 | **검증을 어디까지** — 빠졌을 때 거부하나 | §5 |

## 2. 지금 누가 채우나

**셋이고 규약이 없다.**

| 생산자 | 무엇을 넣나 |
|---|---|
| **트윈 클라이언트** (`mcp_server._end_task`) | 에이전트가 넘긴 metadata 에 **서버가 기억한 `scene` · `seed` · `objects` 를 `setdefault` 로 합친다** |
| **`teleop_keyboard`** | **아무것도 안 넣는다** — "키 하나로 끝내는 UI 라 성패를 줄 수단이 없다"(코드 주석). `outcome` 도 빈다 |
| 수동 `ros2 service call` | 사람이 적는 대로 |

**트윈의 방식이 옳은 선례다.** 주석이 이유를 적어 두었다:

> 재현의 근거는 seed 가 아니라 **실제 배치**다 — 추출 방식이 바뀌면 같은 seed 가 다른 배치를 만들기 때문이다. 에이전트가 넘긴 metadata 에 서버가 기억한 배치를 합쳐 둔다.

**즉 "시스템이 아는 것은 시스템이 채운다"** 이고, 호출자는 자기만 아는 것(작업 의도 등)을 더한다. R4 는 이 원칙을 넓히는 일이다.

⚠️ **그런데 트윈만 그렇게 한다.** `teleop_keyboard` 로 모은 에피소드는 metadata 가 **통째로 빈다** — `backend` 도 없다. teleop 출처를 수집 범위에 넣는 순간(수집 설계 D1 은 지금 범위 밖이라고 적는다) 그 에피소드들은 **어느 스택에서 나왔는지 알 수 없는 데이터**가 된다.

## 3. 언제 채워지나 — 종료 시점뿐이다

`SessionCommand.metadata` 는 **에피소드 종료 전이에서만** 채워진다. 노드가 그렇게 정했고 이유도 적혀 있다:

> `outcome` / `metadata` 는 **에피소드 종료 전이에서만** 채운다. 다른 전이는 기본값('')을 그대로 쓴다 — 그래야 후처리기가 이 값을 종료되는 에피소드에만 귀속시킬 수 있다.

**귀속 규칙으로는 맞다. 그런데 기록 시점으로는 어긋난다.**

| | |
|---|---|
| **아는 시점과 기록 시점이 다르다** | `backend` · `publish_rate` · 계획 파이프라인은 **스택을 띄울 때 정해진다.** 에피소드가 끝날 때 적는 것은 그 사실을 끝까지 들고 있다가 옮겨 적는 일이다 |
| **끝나지 않으면 잃는다** | 스택이 죽거나 rosbag 이 SIGKILL 로 끊기면 `stop_episode` 가 안 불린다. **영상·관절·궤적은 남았는데 조건만 사라진다** |
| **호출자에게 의존한다** | 종료를 부르는 쪽이 metadata 를 함께 넘겨야 하므로, §2 의 teleop 처럼 **안 넘기면 그만**이다 |

**대안은 "시스템이 기본값을 들고 있다가 합친다"** 이다 — `session_control_node` 가 launch 파라미터로 받은 값을 종료 메시지에 merge 하면, 호출자가 무엇을 넘기든 채워진다. 귀속 규칙(종료 전이에만 싣는다)은 그대로 둔 채 **출처만 바꾸는 것**이다.

`rdfp_collect.launch.py` 는 이미 `backend:=mock` 을 인자로 받으므로 **그 값이 노드까지 내려가는 길이 이미 있다.**

## 4. 무엇을 담을 것인가

미구현 목록 R4 가 세는 키는 여섯이다 — `backend` · 속도 배율 · 펑션베이 `publish_rate` · 씬 · 계획 파이프라인 · 생성 호스트. **대조해 보니 하나는 빼야 하고 하나는 더해야 한다.**

| 키 | 판정 |
|---|---|
| `backend` | **담는다.** 지금 `episode_backend()` 가 읽으려는 값이고 항상 `None` 이다 |
| ~~속도 배율~~ | ⚠️ **빼야 한다 — 이미 R1 이 연산마다 싣는다.** `motion_trajectories.velocity_scaling` · `time_scaling` 이 컬럼으로 있다. **입도도 그쪽이 맞다** — 배율은 연산마다 다를 수 있는데 에피소드에 하나로 적으면 거짓이 된다 |
| `publish_rate` (펑션베이) | **담는다.** R1 에 없고 설정 파일에만 있다. 나중에 바뀌면 그 에피소드가 어느 값이었는지 알 길이 없다 |
| 씬 | **담는다.** 트윈이 이미 `scene` · `seed` · `objects` 로 넣고 있다 — 규약에 편입만 하면 된다 |
| 계획 파이프라인 | **담는다** (OMPL · PILZ · CHOMP 중 무엇으로 풀었나) |
| 생성 호스트 | **담는다** — 재현과 추적용 |
| **중력 보상 설정** | ⚠️ **더해야 한다** — [Q13 문서](Q13_중력_보상_기록_고려사항.md) §3 이 요구하는 값이다. 백엔드 프로파일의 `motion.gravity_compensation` 블록(`urdf` · `kp` · `scale`)을 그대로 싣는다 |

**담지 말아야 할 것의 기준이 있다.**

| 기준 | 예 |
|---|---|
| **더 고운 입도로 이미 기록되는 것** | 속도 배율(R1), 연산 결과(R2), 프레임 시각(sidecar) |
| **구조가 커서 따로 두는 것** | 기구학 모델 스냅샷 — **R3/I2 가 별도 채널·테이블로 간다.** metadata 에는 그 **지문(해시)만** 둘지가 열린 질문(§10 Q3) |
| **나중에 조회로 알 수 있는 것** | 토픽 목록 — bag 과 `topics` 테이블에 있다 |

**남는 기준은 하나다: "녹화 시점에만 알 수 있고, 다른 데 안 남는 것."**

## 5. 검증을 어디까지 할 것인가

지금 검증은 **"JSON object 인가" 하나**다(`_is_json_object`). 키 이름을 틀려도, 필수 키가 없어도 통과한다.

| | 방법 | 대가 |
|---|---|---|
| (가) | 지금처럼 **형식만** | 오타가 조용하다. `backend` 를 `bakend` 로 적어도 통과하고, 읽는 쪽은 `None` 을 본다 |
| (나) | **필수 키가 없으면 `stop_episode` 를 거부** | ⚠️ **에피소드가 이미 녹화된 뒤에 거부하는 것**이라, 수집 한 회차를 망친다. 가장 나쁜 시점의 실패다 |
| (다) | **없으면 시스템 기본값으로 채우고, 모르면 경고** | §3 의 대안과 짝이 맞는다. 거부하지 않으므로 수집을 안 망친다 |
| (라) | 적재에서 검사 | 늦다 — 그때는 고칠 방법이 없다(bag 안의 값이 이미 그렇다) |

**(나) 는 피해야 한다.** `set_task_label` 이 `IN_EPISODE` 에서 거부되고 **빈 라벨로 시작한 에피소드는 재적재로도 못 고친다**는 것이 이미 알려진 함정이다(절차서 §4). 종료를 거부하면 같은 종류의 함정을 하나 더 만든다.

## 6. 키가 늘어날 때

**옛 에피소드에는 새 키가 없다.** 읽는 쪽이 **없음을 기본값으로 바꾸면 안 된다** — 이미 그 원칙을 지키는 선례가 있다:

```
backend is unknown — episode metadata did not record it (R4)
```

`build_metadata` 가 `notes` 에 남기는 문장이다. **"모른다"와 "그 값이다"를 구분한다.** 규약에 버전을 붙일지(`metadata_version`)는 열린 질문(§10 Q4)이지만, **키 단위로 "없으면 모른다"** 가 성립하면 버전 없이도 자란다.

## 7. 권고

**순서가 있다. 키 목록(Q5)을 정하기 전에 배선을 정한다.**

| 단계 | 무엇 | 왜 |
|---|---|---|
| **1** | **`session_control_node` 가 launch 파라미터로 받은 기본 metadata 를 종료 메시지에 merge 한다** | §2·§3 의 구멍을 한 번에 막는다 — 호출자가 무엇을 넘기든, teleop 이든, 채워진다. 귀속 규칙은 그대로다 |
| **2** | **`rdfp_collect` 가 백엔드 프로파일에서 값을 뽑아 그 파라미터로 넘긴다** | `backend` 는 이미 인자다. `publish_rate` · 중력 보상 블록도 같은 프로파일에 있다 |
| **3** | **키 목록을 확정한다 (Q5)** — §4 의 판정표 | 1·2 가 있으면 키를 더하는 일이 **launch 한 줄**이 된다 |
| **4** | 호출자가 더할 것(작업 의도, 성패 사유)은 그대로 `StopEpisode` 로 | 트윈의 `setdefault` 방식을 유지 — **호출자 값이 이긴다** |

**1 을 먼저 두는 이유**는 §2 다. 키를 아무리 잘 골라도 **teleop 처럼 안 넣는 생산자가 있으면 빈다.** 시스템이 채우면 생산자 수와 무관해진다.

**merge 규칙은 트윈을 따른다** — `setdefault`, 즉 **호출자가 준 값이 이긴다.** 사람이 일부러 덮어쓴 것을 시스템이 되돌리면 안 된다.

## 8. 검증

| 확인할 것 | 합격 기준 |
|---|---|
| **teleop 에피소드에도 `backend` 가 있다** | `teleop_keyboard` 로 수집한 에피소드의 `sessions.metadata` 에 값이 있다. **지금은 `{}` 다** |
| 호출자 값이 이긴다 | 트윈이 `scene` 을 넘기면 시스템 기본값이 덮어쓰지 않는다 |
| 종료를 거부하지 않는다 | 필수 키가 없어도 `stop_episode` 가 성공한다 — 경고만 남는다 |
| `export` 가 읽는다 | `episode_backend()` 가 `None` 이 아니고, `build_metadata` 의 `backend is unknown` note 가 사라진다 |
| **입도가 겹치지 않는다** | 속도 배율이 metadata 에 **없다** — `motion_trajectories` 가 갖는다 |
| 옛 에피소드 | 키가 없는 에피소드를 읽어도 **죽지 않고 "모른다"로 다룬다** |

## 9. 주의

- ⚠️ **`stop_episode` 를 거부하면 안 된다** — 에피소드가 이미 녹화된 뒤라 고칠 방법이 없다. `set_task_label` 이 `IN_EPISODE` 에서 거부되어 **빈 라벨로 시작한 에피소드를 재적재로도 못 고치는** 것과 같은 함정이다.
- ⚠️ **속도 배율을 metadata 에 넣지 않는다** — R1 이 연산마다 싣고 있어 **중복이면서 입도가 거칠다.** 두 값이 어긋나면 어느 쪽이 참인지 알 수 없다.
- ⚠️ **`seed` 는 재현의 근거가 아니다** — 트윈 주석이 적어 둔 것이다. 추출 방식이 바뀌면 같은 seed 가 다른 배치를 만든다. **실제 배치(`objects`)가 근거다.**
- **`sessions.metadata` 는 jsonb 라 스키마 변경 없이 키가 는다** — 그래서 싸지만, 그래서 **오타도 조용하다**(§5).

## 10. 열린 질문

| # | 질문 | 정하는 방법 |
|---|---|---|
| Q1 | 키 이름과 중첩 — 평평하게(`backend`, `publish_rate`)인가 묶어서(`stack: {...}`)인가 | `metadata->>'backend'` 로 조회하는 코드가 이미 있다(`episode_backend`). **평평한 쪽이 조회가 싸다** |
| Q2 | 시작 시점에도 남길 것인가 | §3 의 귀속 규칙을 바꾸는 일이다. **1단계(시스템 merge)가 되면 필요가 줄어든다** — 다만 끝나지 않은 에피소드의 조건은 여전히 안 남는다 |
| Q3 | 기구학 지문(R3/I2)을 metadata 에도 둘 것인가 | 스냅샷 본체는 별도 채널이지만 **해시만 metadata 에 두면** export 가 조인 없이 읽는다. `ExportSpec.kinematic_model_hash` 가 그 값을 기다린다 |
| Q4 | `metadata_version` 을 둘 것인가 | §6 의 "키 단위로 없으면 모른다"가 성립하면 필요 없다. **키를 지우거나 뜻을 바꿀 때** 필요해진다 |
| Q5 | teleop 출처를 수집 범위에 넣을 때 무엇이 더 필요한가 | 수집 설계 D1 이 지금은 범위 밖이라고 적는다. 넣으면 **§2 의 빈 metadata** 와 **servo 경로 무보상**(R8 §9)이 함께 온다 |

| `robot-twin-client` `mcp_server.py` `_end_task` | `setdefault('scene'/'seed'/'objects')` | **선례** — 시스템이 아는 것을 합친다(§2) |
| `rdfp/teleop/teleop_keyboard.py` | 에피소드 종료 처리 | ⚠️ **`outcome`·`metadata` 를 비워 부른다**(§2) |
| `rdfp/dataset/export/dataset_meta.py` | `episode_backend` · `build_metadata` | 소비자. 없으면 `notes` 에 "unknown" 을 남긴다(§6) |
