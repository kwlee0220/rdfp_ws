## 1. 저장/관리기의 ROS 결합도 측정 (세로 축)

### 1.1 세로 축 검토 당시 (날짜 미기록)

| 지표 | 값 |
|---|---|
| `dataset` + `rosbag` 파이썬 파일 | 61개 (테스트 제외) |
| 그중 **실제 ROS import** 가 있는 파일 | **16개 (26%)** |
| CLI 진입점 (`import`/`stats`/`list`/`init-db`) | **ROS 없이 import 된다** |
| `rclpy` 를 쓰는 파일 | 4개 — **전부 재생 경로** |

당시의 우발적 결합은 ingest 경로가 `sensor_msgs.msg.Image` 를 최상위에서 import 해
`rdfp.dataset.ingest.pipeline` 이 ROS 없이 import 되지 않는 것이었다.

### 1.2 2026-10-18 재측정

AST 로 import 문을 셌다(테스트 제외, 지연 import 포함).

| 지표 | 값 |
|---|---|
| `dataset` + `rosbag` 파이썬 파일 | 78개 (그 사이 생긴 `export/` 7개 포함) |
| 그중 **ROS import** 가 있는 파일 | **20개 (25%)** — 최상위 import 는 9개, 나머지는 지연 import |
| ROS 없이 **실행되는** CLI | `export` · `stats` · `list` · `init-db` · `rosbag` 조회 (`import` 는 모듈만 로드되고 실행은 실패한다) |
| `rclpy` 를 쓰는 파일 | 4개 — `db/mp4_image_replayer.py` · `db/topic_message_replayer.py` · `replay_cmd.py` · `replay_gui_cmd.py` |

최상위 ROS import 9개: `db/_image_helpers.py` · `db/image_message_reader.py` ·
`db/mp4_image_replayer.py` · `db/topic_message_replayer.py` · `ingest/media/ffmpeg_sink.py` ·
`ingest/media/mp4_image_recorder.py` · `replay_cmd.py` · `replay_gui_cmd.py` · `types.py`.
앞의 넷과 재생 CLI 둘은 본질적 결합(재생), `ingest/media/` 둘과 `types.py`(타입 힌트용
`Header`)는 우발적 결합이다. `export/` 에는 ROS import 가 없다.

같은 날 `robot_twin` 은 12개 파일 중 ROS 없이 import 되지 않는 것이 2개(`runtime` ·
`variables`)였다(`backends` · `main` 은 지연 import).

## 2. 제어 계층 분리 과정 (가로 축)

단일 `rdfp` 패키지를 네 패키지(`rdfp_msgs` · `robot_control` · `robot_twin` · `rdfp`)로 나눈
작업의 기록이다.

### 2.1 절단선의 근거 — 이미 존재하던 구조

서브패키지 간 import 를 전수 조사한 결과, 계층을 **역행하는** 의존은 단 하나였다.

| 방향 | 개수 |
|---|---|
| 계층 내부 또는 위→아래 (`dataset → moveit` 등) | 전부 |
| 아래→위 (`twin → session`) | **1개** — `runtime.py` 의 지연 import 한 줄 |

즉 새 선을 그은 것이 아니라 있던 선을 드러낸 것이다.

### 2.2 세 가지 실무 걸림돌과 해법

| 걸림돌 | 해법 |
|---|---|
| launch helper 가 `sys.path.insert(0, dirname(__file__))` sibling 트릭에 묶여 있었다. 한 디렉터리 안에서만 동작하므로 패키지가 갈라지면 상위 launch 가 하위 helper 를 못 가져온다 | `robot_control.launch_helpers` 설치 모듈로 승격. 당시 13개 launch 전부 정규 import 로 전환 (묶음 launch 를 지운 2026-10-18 기준 8개) |
| `twin → session` 역방향 의존 | `robot_twin.backends` **entry point 그룹**. 수집 계층이 팩토리를 등록하고 트윈은 조회만 한다. 미설치면 세션 연산만 비활성화되고 트윈은 정상 기동한다 |
| 경계 침식 | `test_layer_boundary.py` — 패키지 내 모든 소스를 AST 파싱해 상위 계층 import 를 실패시킨다. `package.xml` 의존은 빌드 순서만 강제할 뿐 import 방향을 막지 못한다 |

세 번째가 설계서 §7.3 의 "경계는 문서가 아니라 테스트로 지켜야 한다"의 실행이었다.
