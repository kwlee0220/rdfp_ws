## 1. 여섯 단계와 산출물

```
① 준비      빌드 · DB 스키마 · 데이터 루트                          [rdfp_ws · ROS]
     ↓
② 생성·수집  로봇을 움직이고(생성) 그것을 에피소드로 자른다(수집)    [rdfp_ws · ROS]
     ↓        → rosbag(비영상 채널) + 레코더 mp4(영상) + sidecar
③ 적재      rosbag + mp4 → PostgreSQL                               [rdfp_ws · ROS]
     ↓        → episodes · joint_states · motion_trajectories · image_frames …
④ export    DB → 학습 샘플 트리                                     [rdfp_ws · ROS]
     ↓        → metadata.json + episodes.jsonl + 에피소드별 .npz
═════════════ 여기서 셸이 바뀐다 — 위는 ROS, 아래는 ROS 없음 ═════════════
⑤ 학습      학습 샘플 + mp4 → 정책 체크포인트                       [rdfp-train · ROS 없음]
     ↓        → 정책 + 전처리기 + rdfp_spec.json
⑥ 추론 배치  체크포인트 → 로봇                                       [미구현 — P1~P3]
```

**②가 한 덩어리인 것이 요점이다.** 로봇을 움직이는 것(생성)과 그것을 잘라 기록하는 것
(수집)은 **같은 시간에 같이 일어난다** — 수집 계층이 떠 있지 않으면 아무리 로봇을 잘
움직여도 데이터가 한 건도 안 남는다. 순서가 아니라 겹침이다.

**④와 ⑤ 사이에서 저장소와 셸이 함께 바뀐다.** ①~④는 `rdfp_ws` 에서 `.rdfprc` 를 소싱한
셸로, ⑤는 `~/development/rdfp/rdfp-train` 에서 **소싱하지 않은 셸**로 한다. 경계가
**파일**(`.npz` · json · mp4)이라 두 환경이 만날 일이 없다(§5 의 ③ → ④).

## 2. 전 과정 명령 한 화면 — Isaac

실제 수집 경로(Isaac)다. mock·펑션베이는 §4.

```bash
# ── ②  생성·수집 ────────────────────────────────────────── [ROS 셸]
# 터미널 1 — 시뮬레이터 (2분쯤). [bringup] PLAY 뒤 /clock 이 도는지까지 보고 넘어간다
cd ~/development/ros/rdfp_ws
./scripts/run_isaac_sim.sh --headless

# 터미널 2 — 로봇 스택 + 트윈 + 수집 계층 + rosbag 을 한 번에
#   ⚠️ .rdfprc 를 먼저 소싱한다 — 안 하면 ~/rdfp_data 에 모여 ⑤ 가 못 찾는다 (§5)
cd ~/development/ros/rdfp_ws && source ./.rdfprc
./scripts/run_collect_isaac.sh --with-stack --shutdown rdfp

# 터미널 3 — 작업 수행 (끝나면 터미널 2 가 스스로 정리한다)
cd ~/development/mdtpy/robot-twin-client && .venv/bin/robot-twin-collect --repeat 20

# ── ③ 적재 · ④ export ──────────────────────────────────── [ROS 셸]
cd ~/development/ros/rdfp_ws && source ./.rdfprc
ros2 run rdfp import --config "$RDFP_DATA_ROOT/dataset.yaml"
ros2 run rdfp export --config "$RDFP_DATA_ROOT/dataset.yaml" --out "$RDFP_DATA_ROOT/datasets/v1"
#   적재한 bag 은 rosbag_dir 밖으로 뺀다 (§5 — 명령은 런북 §2)

# ── ⑤ 학습 ─────────────────────────────────────────────── [새 셸 · ROS 없음]
#   ⚠️ .rdfprc 를 소싱하지 않은 셸이다. Isaac 은 내려 둔다 (GPU 를 나눠 쓰지 않는다)
cd ~/development/rdfp/rdfp-train
uv venv --python 3.10 && uv pip install -e .          # 처음 한 번

# 배선 확인 — 40 스텝, 1분 안쪽. 손실이 내려가고 "[train] 저장:" 이 찍히면 된다
.venv/bin/python -u -m rdfp_train.train \
    --root /data/rdfp/datasets/v1 --recordings /data/rdfp/recordings \
    --steps 40 --save-every 0 --out /tmp/smoke && rm -rf /tmp/smoke

# 본 학습 — 기본 20,000 스텝 (⚠️ -u 를 빼면 파이프 너머로 진행이 안 보인다)
mkdir -p outputs
.venv/bin/python -u -m rdfp_train.train \
    --root /data/rdfp/datasets/v1 --recordings /data/rdfp/recordings \
    --out outputs/act 2>&1 | tee outputs/run.log

# 다른 터미널에서 — 100 스텝마다 loss · samples_per_s (새 터미널이라 절대 경로로)
tail -f ~/development/rdfp/rdfp-train/outputs/act/train_log.jsonl
```

`/data/rdfp` 는 `.rdfprc` 의 `RDFP_DATA_ROOT` 이고, rdfp-train 의 기본값도 같다
(`--root` · `--recordings` 를 빼도 된다). 한 줄이라도 바꾸려면 **정본부터** 본다.

## 4. 백엔드마다 경로가 다르다

| 백엔드 | ②의 한 줄 | 비고 |
|---|---|---|
| **Isaac** | **있다** — `run_collect_isaac.sh --with-stack` | 스택 · 트윈 · 수집 계층 · rosbag 을 함께 띄우고 **띄운 것을 스스로 거둔다.** 시뮬레이터는 포함하지 않는다(기동 2분 + 재기동 시 sim 시계 되감김) |
| mock · mock_jgpc | **없다** | 제어 launch → `rdfp_collect` → rosbag 을 손으로 띄운다 (절차서 §2 · §5) |
| 펑션베이 | **없다** | 위와 같고, Unity + `ros_tcp_endpoint` 가 먼저 떠 있어야 한다 |

**실제 수집은 Isaac 으로 한다** — mock 계열은 물체를 파지할 수 없어 학습 데이터를 만들지
못하고(생성 설계), 펑션베이는 시뮬레이터가 이 호스트에 없다. 나머지 둘은 **수집
파이프라인을 시뮬레이터 없이 시험할 때** 쓴다. ③~⑤는 백엔드와 무관하게 같다.

## 5. 단계 사이에서만 생기는 함정

**각 단계 안의 함정은 그 단계 정본이 갖는다.** 여기 있는 것은 **경계에 걸쳐 있어 어느
문서도 자기 것이라 하지 않는** 것들이다. 대부분 **오류가 아니라 빈 결과나 나쁜 성능**으로
나타난다. 소리를 내고 서는 것은 셋뿐이다 — `import` 의 UNIQUE 제약 위반(② → ③),
ROS 없는 셸의 `ModuleNotFoundError`(③ → ④), 학습 기동 시점의 `FileNotFoundError`(④ → ⑤).

### ① → ② 수집 계층을 안 띄우면 아무것도 안 남는다

로봇은 잘 움직이고 트윈도 성공을 돌려주는데 데이터가 0 건이다. `/session` 을 건드리는
주체가 없어 **에피소드 경계가 안 생기기** 때문이다.

⚠️ **`robot-twin-stack` 은 수집에 못 쓴다** — 쌓기만 반복하고 `/session` 을 안 건드린다.
2026-09-20 에 9회를 그렇게 돌려 한 건도 못 건졌다. 수집용은 **`robot-twin-collect`** 다
(한 에피소드가 `reset_scene → return_home → start_episode → 작업 → verify → stop_episode`
한 바퀴). **실패한 회차도 닫아서 남긴다**(`outcome=failure`) — 안 닫으면 다음
`start_episode` 가 409 로 거부되어 그 뒤 회차가 통째로 경계를 잃는다.

### ① → ② 설정을 고쳤으면 `colcon build` 를 해야 반영된다

같은 장면을 **세 주체가 읽는다** — Isaac 스테이지(`scripts/isaac/sim_side/*`), 트윈
(`run_robot_twin.sh`), scene 노드. **셋 다 설치본(`install/`)을 읽는다** (2026-09-21).
`src/` 의 `isaac_scene.json` · `robot_twin_panda_isaac.yaml` 을 고쳤으면 빌드한 뒤 **Isaac
까지 전부** 다시 띄운다 — 셋 다 기동 시점에만 읽는다.

**예전에는 scene 노드만 설치본을 읽고 나머지 둘은 `src/` 를 읽었다.** 그래서 2026-09-20 에
실린더 반지름(0.025 → 0.03)과 탁자 높이(0.4 → 0.3)를 `src/` 에서만 고친 뒤 수집을 걸자,
트윈이 `[0.06, 0.03]` 을 요청하고 scene 노드가 설치본의 `[0.06, 0.025]` 와 대조해
**매 회 `reset_scene` 을 거부했다.**

⚠️ **거부된 것은 운이었다** — 반지름이 바뀌어 치수 검사에 걸렸을 뿐, scene 노드는 **위치를
검사하지 않는다.** 탁자 높이만 바뀌었다면 물체를 10 cm 틀린 높이에 놓고 **조용히 수집했을
것이다.** 지금은 셋이 같은 곳을 읽으므로, 빌드를 잊으면 셋 다 **똑같이 옛 값**을 봐서
갈라지지 않고 *"고쳤는데 안 바뀐다"* 로 드러난다. 시험
(`test_isaac_sim_side_scripts.py` 의 `*_install_tree`)이 누가 다시 `src/` 로 돌려놓는 것을 막는다.

### ② 안에서 — 라벨은 에피소드 *시작 전에* 정한다

`set_task_label` 은 `IN_EPISODE` 에서 **거부되고**, 빈 라벨로 시작한 에피소드는
**재적재로도 못 고친다**(bag 안의 `/session` 메시지가 이미 비어 있다).

### ② → ⑤ 데이터 루트가 단계마다 같아야 한다

`run_collect_isaac.sh` 는 `$RDFP_DATA_ROOT` 가 없으면 **`~/rdfp_data`** 에 모으는데,
`.rdfprc` 는 그것을 **`/data/rdfp`** 로 두고 rdfp-train 의 기본값도 `/data/rdfp` 다.
`.rdfprc` 를 소싱하지 않고 수집하면 ②는 `~/rdfp_data` 에, ⑤는 `/data/rdfp` 를 본다.
§2 의 명령이 매번 `source ./.rdfprc` 부터 하는 이유다.

### ② → ③ 적재한 bag 을 `rosbag_dir` 밖으로 뺀다

시뮬레이터를 재기동하면 sim 시계가 0 으로 되감기므로 **에피소드 키
`(start_sec, start_nanosec)` 가 회차 간에 유일하지 않다.** 옛 bag 과 새 bag 을 같은
디렉터리에서 함께 적재하면 새 에피소드의 관절 데이터가 **0 건**으로 커밋된다.

⚠️ **증상이 "에피소드가 없다"가 아니라 "에피소드는 있는데 속이 비었다"** 이다 —
`image_frames` 는 레코더 sidecar 의 `episode_key` 로 붙으므로 **이미지만 정상으로 들어가**
겉보기에 멀쩡하다. 확인은 적재 뒤
`select count(*) from joint_states where episode_id=…` 가 0 인 에피소드를 찾는 것이다.

치우는 명령은 [isaac_bringup_runbook.md](../backends/isaac/isaac_bringup_runbook.md) §2 에
있다 — **세션 단위로** 옮긴다(날짜 디렉터리째 `mv` 하면 같은 날 두 번째부터 조용히 실패).

### ② → ③ 녹화 목록과 `topics_file` 이 같은 파일을 가리켜야 한다

`config/recording_topics.list` 는 mock 기준이라 Isaac 에 그대로 쓰면 이미지가 한 장도 안
담긴다. Isaac 은 `recording_topics_isaac.list` 이고, **`dataset_config.yaml` 의
`topics_file` 도 같은 것**이어야 한다.

⚠️ 지금은 **녹화 목록에서 이미지 토픽을 빼야 한다** — 안 빼면 bag 의 이미지와 레코더
mp4 가 같은 `(episode_id, topic_id)` 로 `image_streams` 에 들어가려다 UNIQUE 제약에
걸려 `import` 가 죽는다.

### ② → ⑤ 카메라가 프레임을 건너뛰고, 그것이 학습에서 드러난다

②에서 생기고 ⑤에서야 보이는 특성이다. 2026-09-20 수집분 65 에피소드의 프레임 간격이
**중앙값은 정확히 100 ms(설정 10 Hz)** 인데 **15.2 % 가 200 ms 를 넘고** 최대 2100 ms 다.
간격이 100 ms 의 정수배라 느려진 것이 아니라 **렌더를 통째로 거른다**.

⚠️ **`metadata.json` 의 `camera_hz` 는 평균이라 이 구조를 못 보여준다.** frame clock 이
실제 stamp 를 쓰므로 레이블은 정합하지만, 그 15 % 구간에서 관측 하나에 행동 여러 스텝이
묶인다. **학습 결과가 안 좋을 때 후보 원인 중 하나다** — 수집 쪽을 고쳐야 없어진다.

### ② ↔ ⑤ GPU 를 나눠 쓰지 않는다

Isaac(②)과 학습(⑤)이 같은 기계면 **둘 다 느려진다.** 학습 중에는 Isaac 을 내린다
(`kill_stack.sh`). ⑥ 추론은 학습이 끝난 뒤라 겹치지 않는다.

### ③ → ④ ROS 경계는 export 다

**적재는 ROS 가 필요하고 export 는 아니다.** `import` 는 소싱 안 한 셸에서
`ModuleNotFoundError` 로 죽지만(`ffmpeg_sink` 의 `sensor_msgs` import), `export/` 에는
ROS import 가 한 줄도 없고 산출물도 numpy·json 뿐이다. **그래서 학습은 ROS 밖에서 한다.**

다만 **"ROS 밖이니 파이썬이 자유롭다"는 이론일 뿐이다** — ⑤는 실제로 **3.10 에 고정**이다
(아래 §6). 자유를 제약하는 것은 ROS 가 아니라 ⑥ 배치다.

### ④ → ⑤ 두 셸이 필요하다 — 재export 는 ROS 셸, 학습은 아니다

에피소드를 더 모았거나 다시 적재했다면 **학습 전에 export 를 다시 한다.** 그 명령만은
`rdfp_ws` 에서 `.rdfprc` 를 소싱한 셸에서 한다. 학습은 소싱하지 **않은** 셸에서 한다 —
한 셸로 둘 다 하려 하면 어느 한쪽이 깨진다.

### ④ → ⑤ export 트리와 mp4 의 **관계**를 유지한다

`episodes.jsonl` 의 `mp4` 는 **파일 이름뿐**이다(`"session_20260920-162849.763.mp4"`).
절대 경로가 아닌 것은 **다른 머신으로 옮길 수 있게** 하려는 것이라, 학습은
`--root`(export 트리)와 `--recordings`(mp4 디렉터리)를 **따로** 받는다. 옮길 때는
`datasets/v1/` 과 `recordings/*.mp4` **둘 다** 옮긴다(`.jsonl` · `_metadata.json` sidecar 는
적재 때만 쓰므로 안 옮겨도 된다). `rdfp_ws` 는 안 옮겨도 된다. 명령은 rdfp-train
README 「D4」 §1.

이름이 안 맞으면 `Dataset` 이 **기동 시점에** `FileNotFoundError` 로 거부한다 — 학습을
시작해 놓고 뒤늦게 깨지지 않는다.

### ⑤ → ⑥ 체크포인트는 **셋**이 한 묶음이다

`outputs/act/final/`(그리고 `step_XXXXXX/`)에 셋이 함께 있어야 추론에 쓸 수 있다.

| 파일 | 빠지면 |
|---|---|
| 정책 (`save_pretrained`) | 가중치가 없다 |
| **전처리기** (`save_pretrained`) | **추론 노드가 정규화 안 된 원값을 먹인다** — `lerobot` 0.4.4 에서 정규화는 정책 밖의 파이프라인이다 |
| `rdfp_spec.json` | 수집 쪽 배치 규약(`ExportSpec`) · 스텝 · 카메라 이름 · 쓴 chunk 길이 |

⚠️ **전처리기나 규약이 어긋나도 에러가 안 난다** — 증상은 *"학습은 됐는데 로봇이 이상하게
움직인다"* 뿐이다. 카메라 주기 · Δ · 행동 스텝 · k · 그리퍼 심볼 순서가 학습 때와
배치 때 같아야 하고(ACT 문서 §7), 그 대조가 `ExportSpec.assert_compatible()` 이다(E6).
**배치 쪽에서 그것을 실제로 부르는 것이 미구현 목록 P3** 다.

## 6. ⑤ 학습 — 어디까지 됐나

**`~/development/rdfp/rdfp-train`** 이 학습기다 — `rdfp_ws` 밖의 별도 저장소이고
ROS 가 없다. 진척의 정본은 추론기 배치 문서 §3.1 의 **D 행**이다.

| | 상태 |
|---|---|
| D1 환경 | ✅ Python **3.10** · `lerobot==0.4.4` · torch 2.10.0+cu128 · PyAV |
| D2 `Dataset` (`dataset.py`) | ✅ `.npz` 행 + mp4 프레임 → 배치 dict. 무작위 접근 프레임 불일치 0 |
| D3 학습 루프 (`train.py`) | ✅ 40 스텝 시험 주행에서 손실 41.0 → 7.1 |
| **D4 학습 실행** | **다음** — 65 에피소드 · 11,719 샘플 · `chunk_len` 20 (2026-09-20 수집분) |

### 환경이 **3.10 에 고정**인 이유

`requires-python = ">=3.10,<3.11"` 이고 `lerobot==0.4.4` 다. **둘 다 ⑥ 때문이다** —
`lerobot` 0.5.0 부터 Python ≥ 3.12 를 요구하는데 **추론 노드는 ROS Humble 의 3.10** 에서
돈다. 학습만 올리면 노드 쪽에 변환 단계(TorchScript·ONNX)나 프로세스 분리가 생긴다.

**이 제약은 LeRobot 고유가 아니다** — ACT 를 직접 가져와도 노드가 3.10 용 `torch` 를
써야 한다. *"학습 스택을 ROS 노드에 들인다"* 는 선택의 제약이다.

### 정해진 것

| 항목 | 결정 |
|---|---|
| 데이터셋 형식 | **LeRobot 형식을 쓰지 않는다** — 우리 `.npz` (단일 fps 전제를 벗어난다, E7 §3.2) |
| 정책 | **`lerobot` 의 `ACTPolicy` 를 그대로** 쓴다. 접점은 파일 포맷이 아니라 **배치 dict** 다 |
| 영상 읽기 | **PyAV** — `cv2.CAP_PROP_POS_FRAMES` 는 프레임당 21.51 ms 로 4.8 배 느리다 (E7 부록 C) |

### 남은 것

- **검증 분할이 없다 — 멈출 지점의 근거가 없다.** `--steps 20000` 은 관례일 뿐이고, 과적합이
  와도 손실 곡선의 모양으로만 짐작하게 된다. 65 에피소드는 작아 일찍 올 수 있다.
- **⑥ 추론 배치 전부** — 추론 노드(P1) · 컨트롤러 어댑터(P2) · 조건 대조(P3).

## 7. 되돌리기

모은 것을 지우고 다시 시작하려면(씬·조명을 바꿔 옛 데이터가 섞이면 안 될 때)
[dataset_postproc_user_guide.md](dataset_postproc_user_guide.md) **§8.6** 이
다섯 덩어리(DB · 적재 대기 bag · 보관 bag · 레코더 mp4 · 학습 샘플)를 한자리에 모아 둔다.
**⑤의 체크포인트(`rdfp-train/outputs/`)는 그 다섯에 없다** — 저장소가 달라서다. 하나가
197 MB, 기본 설정이면 약 1 GB 다.

⚠️ **`scripts/clear_dataset.sh` 로는 판이 안 비워진다.** 이름과 달리 실질적으로 **DB 만
지운다** — 그것이 지우는 `videos/` 는 `FrameRouter` 가 rosbag 이미지 토픽에서 뽑는 mp4 라,
녹화 목록에서 카메라 토픽을 뺀 지금은 보통 **비어 있다.** 실제 영상 원본인 **세션 레코더의
`recordings/` 는 그대로 남는다.** (스크립트가 끝나면서 남은 것을 세어 알려 준다.)
